
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：公司名 / 工厂名 / 产品名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "v2.1.159"、"Small is a feature"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "Rubin Ultra" + 来源 "NVIDIA News" → "英伟达发布 Rubin Ultra 服务器平台"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"服务器新品"）兜底，绝不凭"行业常识"编一个具体型号 / 版本 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的工厂、产品或新数据，就改写成“投产 / 发布 / 落地 / 开工”。只有原标题明确宣布了投产、发布、推出或开工，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、工厂、项目名。
   例：原标题 "How Quanta ramps AI server production in Mexico" → "广达如何在墨西哥爬坡 AI 服务器产能"，不能写成 "广达发布墨西哥工厂"。
   例：原标题 "A tour of Lenovo's LCFC smart factory" + 来源和正文明确是 Lenovo → "联想 LCFC 智能制造基地巡览"，不能只写成缺主体的 "智能制造基地巡览"。
6. 本条的动作和背景里的旧发布要分清：原文把投产写成过去的事（“At COMPUTEX, we launched …”“Last week we broke ground …”“上周我们开工了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把投产交代成此前的事；不能写成“投产 / 发布 / 开工”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "We broke ground on the new server plant last week … See inside below" → "某厂商展示上周开工的服务器工厂内部"，不能写成 "某厂商上周开工新服务器工厂"。
